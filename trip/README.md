# 🧳 가족 여행 플래너

아이들이 직접 가족 여행 일정을 짜는 드래그 앤 드롭 플래너입니다.
장소/체험/식당 **카드**를 타임라인으로 끌어다 놓으면 하루 일정이 만들어집니다.
여행이 끝나도 지우지 않고, 다음 여행(제주 2027…)을 새로 만들어 계속 씁니다.

`trip/index.html` 하나가 전부입니다 — 빌드 없음, 서버 없음.

## 쓰는 법

0. **📍 가까운 순** — 카드 풀의 필터 칩 끝에 있는 토글. 켜고 Day를 고르면, 각 카드를
   그 날 일정에 끼워 넣을 때 **이동이 몇 분 늘어나는지(+n분)** 계산해 싼 순서로 정렬합니다.
   단순 직선거리가 아니라 우회 시간 기준이라, 동선 뒤쪽 가게가 위로 올라오지 않습니다.
   그 날이 비어 있으면 숙소에서의 시간(🏨 n분)으로 정렬하고, 숙소 카드는 정렬에서 빠집니다.
1. **여행 고르기** — 홈에서 여행 카드를 누릅니다. (＋로 새 여행 만들기)
   - 오는 날이 지난 여행은 자동으로 **🌅 다녀온 여행** 섹션으로 내려가 회색으로 표시됩니다
     (눌러서 보는 건 그대로 됩니다).
   - 여행 카드를 **길게 누르면(또는 우클릭)** 휴지통으로 보낼 수 있습니다. 휴지통(홈 하단 🗑)에서
     **30일 동안 보관**되며 언제든 ♻️ 되살리기, 또는 영구 삭제(확인 후)가 가능합니다.
     30일이 지나면 앱을 열 때 자동으로 정리됩니다. 휴지통도 Firebase로 동기화됩니다.
   - 카드 편집(✏️) 창의 **⧉ 복제** 버튼으로 카드를 복사해 새 카드를 만들 수 있습니다
     (같은 체인의 다른 지점 등록 등).
   - 카드의 위치는 **🔍 장소·주소 검색**(OpenStreetMap, 키 불필요)으로 드롭다운에서 고르거나,
     구글 지도 긴 주소 붙여넣기로 넣습니다. 유명 장소·역·주소는 검색이 잘 되고,
     작은 가게는 구글 링크가 더 정확합니다.
2. **일정 만들기** — 왼쪽(좁은 화면에선 아래) 카드 풀에서 카드를 Day 칸으로 끌어다 놓습니다.
   - 카드의 **높이 = 걸리는 시간** (1분 = 2px). 긴 일정일수록 길쭉합니다.
   - 카드 사이에는 **이동 시간 블록**이 자동으로 끼워집니다. 이 블록의 높이도 이동 시간에 비례합니다.
   - 🔓/🔒 버튼으로 카드를 **고정**하면 끌 수 없고, 다른 카드가 그 자리를 밀어내지 못합니다.
   - 카드를 타임라인 밖으로 끌어내거나 ✕를 누르면 일정에서 빠집니다.
   - Day 머리의 시각을 바꾸면 그날 출발 시각이 바뀌고 모든 시간이 다시 계산됩니다.
   - **🍽 밥때 음영**: 점심(12~13시)·저녁(18~19시)에 해당하는 구간이 주황색 띠로 옅게 덮입니다.
     그 시간대에 먹기 카드가 하나도 없으면 하루 요약 아래에 "🍽 점심 카드가 없어요"라고 알려 줍니다
     (노느라 밥을 잊기 쉬워서요). 띠는 클릭을 통과하므로 드래그에 방해되지 않습니다.
3. **지도** — 일정에 놓인 순서대로 번호 마커가 찍히고 점선으로 이어집니다.
   타임라인 카드에 마우스를 올리면 지도의 마커가 주황색으로 커집니다.
   지도 위의 **[전체] [Day 1] [Day 2]…** 칩으로 보고 싶은 날의 동선만 골라 볼 수 있습니다
   (여행이 길면 모든 날이 겹쳐 읽기 어려워서요). 빈 날을 고르면 화면은 움직이지 않습니다.
4. **카드 만들기 (어른용)** — 위쪽 ➕ 버튼. 이름/종류/걸리는 시간/위도·경도를 넣습니다.
   **구글 지도 링크(PC 주소창의 긴 주소)를 붙여넣으면 위도·경도가 자동으로 채워집니다.**
   폰 공유용 짧은 링크(maps.app.goo.gl)에는 좌표가 없어서, 한 번 열어 긴 주소를 복사해야 해요.
   카드의 ✏️로 고치거나 지웁니다.
4-1. **🔗 카드 사이트 주소** — 카드에 공식 홈페이지·예약 페이지 주소를 붙일 수 있습니다
   (카드 편집 ✏️ 또는 시트의 `사이트` 열). 주소가 있는 카드는 풀에서 ✏️ 옆에 **🔗 버튼**이,
   블록을 탭한 상세창에 **"🔗 자세히 보기"** 버튼이 생기고, 누르면 새 탭으로 열립니다.
   `https://` 없이 적어도 자동 보정되고, http(s)가 아닌 주소는 안전을 위해 버립니다.
5. **블록 체크리스트** — 타임라인에 놓인 블록을 탭하면 상세창이 열리고,
   "꼭 하기 · 잊지 말기" 체크리스트를 붙일 수 있습니다. 블록에는 ✅ 2/3 진행도가 표시됩니다.
   체크리스트는 카드가 아니라 **그 날 그 일정**에 붙습니다 — 같은 카드를 다른 날 또 쓰면 따로 갑니다.
6. **숙소** — 숙소 카드는 체류시간 대신 **체크인 가능/체크아웃 마감 시각**을 갖습니다.
   Day 칸에 끌어오면 타임라인이 아니라 그 날 머리의 **"오늘 밤 숙소"** 슬롯에 들어가요.
   다음 날 아침은 그 숙소에서 출발하는 것으로 이동 시간을 계산하고, 하루의 끝에는
   "🏨 숙소 가기" 이동 블록이 자동으로 붙습니다. 출발 시각이 체크아웃 마감을 넘으면 ⚠️ 경고.
   - **연박**: 끌어다 놓으면 **"몇 밤 묵어요?"** 를 물어 그 날부터 n일 밤을 한 번에 채웁니다
     (여행 마지막 날을 넘지 않게 잘림). 첫날은 `🏨 오늘 밤: A · n박`, 이어지는 날은
     `↳ A · 2박째`로 표시되고, ✕로 뺄 때 연박이면 "이 날만 / 전부"를 고릅니다.
   - **숙소를 옮기는 날**: 전날 숙소와 오늘 숙소가 다르면 `🔄 오늘 밤부터: B` 배지와
     체크아웃 시각, "🧳 짐 옮기는 날" 안내가 뜹니다. 숙소마다 배지의 띠 색이 달라서
     여러 곳에 묵는 여행도 한눈에 구분됩니다. 데이터는 그대로 날짜별(`itins.dayN.stay`)
     한 칸이라, A→B→A처럼 되돌아오는 일정도 자연스럽게 표현됩니다.
   - 마지막 날(밤이 없는 날)에는 "숙소를 끌어오세요" 안내가 뜨지 않습니다.
7. **교통 카드** — 항공편·기차처럼 시각이 정해진 이동은 🚄 교통 카드로 만듭니다.
   출발·도착 시각(선택)과 도착지 좌표(선택)를 넣을 수 있고, 노선·환승·출구 메모는 설명란에.
   타임라인에서 교통 카드 앞에는 자동 이동 블록이 생기지 않고(그 카드가 곧 이동이니까),
   일찍 도착하면 ⏳ 기다리기 블록, **앞 일정이 밀려 출발 시각을 놓치면 ⚠️ "n분 늦어요" 경고**가 뜹니다.
7-1. **⏰ 시작·예약 시각** — 타임라인 블록을 탭해 예약 시각을 넣으면(교통이 아닌 카드),
   일찍 도착하는 만큼 ⏳ 기다리기 블록이, 앞 일정이 밀려 늦으면 ⚠️ 경고가 뜹니다.
   예약 시각은 **그 날 그 블록**에 붙고(같은 카드를 다른 날 쓰면 따로), 동선 검사는 이 블록의
   자리를 지킵니다. 카드(✏️)나 시트의 `예약시각` 열에 넣은 값은 일정에 놓을 때 기본값으로 복사됩니다.
7-2. **👥 나눠 움직이기** — 카드 풀 맨 위의 특수 카드를 타임라인의 원하는 지점에 끌어다 놓고
   가족을 두 팀으로 나누면(칩을 탭해서 이동), 그 지점부터 타임라인이 두 갈래 레인으로 갈라집니다.
   레인마다 카드를 따로 놓고 이동 시간도 따로 계산되며, 분기 아래 첫 공통 카드(또는 오늘 밤 숙소)에서
   **늦게 오는 팀 기준으로 자동 합류** — 먼저 온 팀 레인에는 "⏳ 만나기까지 n분"이 붙습니다.
   지도에서는 팀별로 선 색이 달라집니다. ✎로 팀을 바꾸고, ✕로 없애면 안의 카드는 한 줄로 합쳐집니다.
   가족 명단(이름·이모지)은 홈의 **👪 우리 가족**에서 바꿉니다.
8. **✨ 동선 검사** — Day 아래 버튼. 🔒 고정 카드와 🚄 교통 카드는 자리를 지킨 채
   나머지만 재배열해 이동 시간이 가장 적은 순서를 찾고, *"노는 시간이 n분 늘어나요"* 로
   비교해서 보여 줍니다. 바꿀지는 아이가 고르고, 바꾼 뒤에는 "↩︎ 되돌리기"가 남습니다.
   숙소가 지정돼 있으면 전날 숙소에서 출발해 오늘 숙소로 돌아오는 동선으로 계산합니다.

## 📤 친구에게 HTML 파일로 보내기

플래너 위쪽 **📤** 버튼 → 지금 보고 있는 여행만 담은 **단일 HTML 파일**이 내려받아집니다
(`도쿄 2026 여행플래너.html`). 카카오톡·메일로 보내면 받은 사람은 파일을 열기만 하면 됩니다.

- 여행의 카드·일정·체크리스트가 **파일 안에** 들어 있습니다.
- 받은 사람이 고친 내용은 **그 사람 기기에만** 저장됩니다 — Firebase에 붙지 않으므로
  우리 가족 일정에는 아무 영향이 없습니다. 저장 키도 `trip-planner-shared-v1`로 분리돼 있습니다.
- 지도(Leaflet CDN)만 인터넷이 필요하고, 나머지 기능은 인터넷 없이도 됩니다.
- 사본에서는 📤 버튼이 숨겨집니다(사본은 자기 자신을 다시 만들 수 없습니다).

동작 원리: 앱이 `fetch(location.href)`로 자기 소스를 읽어 `const STANDALONE`을 `true`로,
`const EXPORTED`를 여행 데이터로 치환한 사본을 만듭니다. 그래서 **인터넷 주소(https://…)로 연
앱에서만** 만들 수 있고, 이미 내려받은 파일에서는 만들 수 없습니다(안내 문구가 뜹니다).
소스의 `//__STANDALONE__`, `//__EXPORTED__` 표시는 치환 자리표시자이니 지우면 안 됩니다.

## 여행 데이터를 스프레드시트로 넣기

프로그램을 몰라도 여행 데이터를 넣을 수 있게, **시트 1장 = 여행 1개** 양식이 있습니다:
[`trip-template.xlsx`](trip-template.xlsx)

1. 시트를 복제해서 파란 글씨 칸을 채웁니다 — 위쪽에 여행 이름/가는 날/오는 날,
   아래 표에 카드를 한 줄에 하나씩. 열은:
   - **공통**: 이름 · 종류(체험/먹기/쇼핑/교통/숙소) · 시간(분) · 가격 · 설명 ·
     **지도링크** · 위도 · 경도 · **할일메모** · 예약시각 · **사이트**
   - **숙소용**(초록 머리): 체크인 · 체크아웃
   - **교통용**(파란 머리): 출발시각 · 도착시각 · 도착지도링크 · 도착위도 · 도착경도

   **지도링크** 칸에 구글 지도 긴 주소를 붙여넣으면 위도/경도는 비워도 됩니다
   (좌표 숫자를 직접 넣어도 됨 — 둘 다 있으면 숫자가 우선). 폰 공유용 짧은 링크
   (maps.app.goo.gl)에는 좌표가 없어 못 읽고, 그런 줄은 건너뛰었다고 알려 줍니다.
   **할일메모**는 `예약 확인; 우산 챙기기`처럼 `;`로 구분 — 카드를 일정에 놓는 순간
   그 날의 체크리스트로 복사되어 들어갑니다. 앱의 카드 편집(✏️)에서도 같은 값을 고칠 수 있고,
   할일메모 열이 없는 시트로 다시 가져와도 앱에서 만든 기본 할 일은 지워지지 않습니다.
   구글 시트에 올려서 써도 됩니다 (탭 구분 복사만 되면 아무 스프레드시트나 OK).
   열은 **이름으로 찾기 때문에 순서를 바꾸거나 안 쓰는 열을 지워도 됩니다.**
2. 시트 전체 선택(Ctrl+A) → 복사(Ctrl+C).
3. 앱 홈의 **📋 표에서 가져오기**에 붙여넣기 → 가져오기.

### ☁️ 구글 시트에 연결해 🔄 로 새로고침하기

붙여넣기 대신 **구글 시트 주소로 연결**해 두면, 이후엔 플래너 위쪽 **🔄** 버튼 한 번으로
시트 내용을 다시 읽어 옵니다. (카드만 갱신되고 아이들이 짜 둔 일정은 그대로 남습니다.)

**준비 — 한 번만 하면 됩니다:**

1. ⚠️ **업로드한 `.xlsx` 파일은 안 됩니다.** 드라이브에서 그 파일을 열고
   **파일 → Google 스프레드시트로 저장**해 네이티브 시트로 변환하세요.
2. 변환된 시트에서 **파일 → 공유 → 웹에 게시** → 게시할 **시트(탭)를 선택**하고
   형식을 **쉼표로 구분된 값(.csv)** 으로 → **게시**.
3. 나오는 주소(`…/pub?gid=…&single=true&output=csv`)를 복사해서,
   앱 홈 **📋 표에서 가져오기** 창 아래쪽 "☁️ 구글 시트 주소" 칸에 넣고 **☁️ 주소에서**.

여행마다 시트(탭)가 다르므로 **여행별로 한 번씩** 연결하면 됩니다.
게시된 주소는 링크를 아는 사람이면 볼 수 있고, 구글이 최대 5분쯤 캐시하므로
시트를 고친 직후에는 반영이 조금 늦을 수 있습니다.

앱 → 시트 방향(역방향)은 로그인이 필요해 지원하지 않습니다. **시트는 카드 원본,
앱은 일정**으로 역할을 나누는 구조입니다.

같은 이름의 여행이 이미 있으면 새로 만들지 않고 그 여행을 업데이트하며,
카드도 이름으로 맞춰서 기존 일정이 끊어지지 않습니다. 위도/경도가 빈 줄은 건너뜁니다.

## 데이터 형식 (DB)

Firebase Realtime Database의 `tripPlans` 아래에 통째로 들어갑니다
(localStorage `trip-planner-v1`에도 같은 모양):

```jsonc
{
  "trips":  { "tokyo_2026": { "title":"도쿄 2026", "startDate":"2026-01-02", "endDate":"2026-01-04" } },
  "cards":  { "tokyo_2026": { "c_teamlab": {
      "title":"팀랩 플래닛", "description":"…", "category":"activity",  // activity|food|shopping|accommodation
      "durationMinutes":120, "priceRange":"₩₩₩", "lat":35.6493, "lng":139.7891 } } },
  "itins":  { "tokyo_2026": { "day1": {
      "start":"09:00",
      "stay":"c_hotel",                      // 이 날 밤 숙소 (카드 id)
      "items":[ { "uid":"c_teamlab_x3f2a", "cardId":"c_teamlab", "isFixed":false,
                  "todos":[ { "t":"예약 확인", "d":true } ] } ] } } }
}
```

카드의 선택 필드 — 숙소: `checkIn`/`checkOut`(시각), 교통: `depTime`/`arrTime`(시각)과
`lat2`/`lng2`(도착지 좌표). 교통 카드에 시각이 둘 다 있으면 소요시간은 거기서 계산됩니다.

## 저장

- 항상 이 기기의 localStorage(`trip-planner-v1`)에 저장됩니다. 오프라인이어도 됩니다.
- **처음 연결될 때 이 기기의 일정과 서버의 일정이 서로 다르면**, 덮어쓰기 전에
  "☁️ 일정이 두 벌이에요" 창이 떠서 어느 쪽으로 맞출지 묻습니다(양쪽 요약을 보여 줌).
  한 번 고르고 나면 그 뒤로는 묻지 않고 조용히 같이 편집됩니다.
  아직 아무것도 안 만진 기기이거나 양쪽이 같으면 묻지 않습니다.
- Firebase(`unimai-game-hub`)가 연결되면 `tripPlans` 경로에 동기화되어
  **가족 모두의 기기에서 같은 일정**이 보입니다. 규칙은 리포 루트의
  [`firebase-rules.json`](../firebase-rules.json) 전체를 게시하세요 (조각 게시 금지 — [FIREBASE.md](../FIREBASE.md)).

## 설계 메모 (왜 원안과 다른가)

원래 기획서는 Next.js + Firestore + Google Maps Directions API였지만,
이 저장소는 **빌드 없는 단일 HTML + 공용 Realtime Database + GitHub Pages** 관례라 거기에 맞췄습니다.

- **지도**: Google Maps JS API는 결제 키가 필요해서 **Leaflet + OpenStreetMap**(키 불필요) 사용.
- **이동 시간**: Directions API(대중교통 모드)는 브라우저에서 직접 못 부르고 서버 키가 필요합니다.
  대신 직선거리 × 1.3 보정으로 어림합니다 — 0.9km 이하는 🚶 걷기(75m/분),
  그 이상은 🚇 대중교통(평균 25km/h + 대기 8분). `estTransit()` 한 군데만 고치면
  나중에 진짜 API로 바꿀 수 있습니다.
- **데이터 모델**은 기획서의 trips / cards / itineraries 구조를 그대로 따르되,
  RTDB `tripPlans/{trips,cards,itins}` 아래에 둡니다.
